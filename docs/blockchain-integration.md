# Blockchain integration

`BLOCKCHAIN_DRIVER=mock|http` selects a deterministic local anchor or a timeout/retry-bounded external Node service. `CanonicalJsonSerializer` recursively sorts object keys, normalizes UTC dates, and makes whole-number decimals canonical; the anchor service hashes privacy-safe milestone payloads with SHA-256. It reserves each event hash as `PENDING` under a database lock before external submission, preventing concurrent workers from submitting duplicate anchors. `AnchorTraceabilityEvent` queues anchoring without serializing models. Only hashes, network/contract identifiers, and transaction references leave Laravel; individual readings and secrets never do.

The HTTP client authenticates with a bearer token, retries bounded connection failures, validates submission states, URL-encodes transaction references, and requires a boolean verification result. Every verification attempt is stored without raw provider content; successful verification confirms the transaction, while failed verification is audited and notified once. Terminal submission failures create a sanitized `FAILED` transaction linked to the event. Re-running the job retries that same event hash and updates the existing record.

With `BLOCKCHAIN_AUTO_ANCHOR=true`, only the approved traceability milestones are dispatched after commit; individual telemetry readings are excluded. `fishtrace:poll-blockchain-transactions` queues unique verification jobs for a bounded batch of `PENDING` or `SUBMITTED` records and runs every five minutes through Laravel's scheduler. Terminal polling exceptions persist only a sanitized error class, audit the failure, and notify the affected organization once.

The consumer trace portal derives `VERIFIED`, `PENDING`, or `FAILED` blockchain state from persisted eligible events, anchors, confirmed transactions, and successful verification records. It exposes aggregate counts and verification time only—never hashes, transaction references, contract addresses, or provider responses. The overall trace is labeled `VERIFIED` only when all eligible milestones have independently verified evidence; otherwise it is `TRACE_RECORDED` (or `BATCH_RECALLED` for recalled product).
