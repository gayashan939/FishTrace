# Firebase telemetry synchronization

Run `php artisan fishtrace:sync-firebase-telemetry --limit=250`. The command acquires a cache lock, scans a bounded number of active provisioned devices, skips synchronized entries, validates numeric ranges and the active assignment, inserts by unique message ID, preserves device time, updates device health, and marks Firebase metadata. `--retry-failed` processes only Firebase records marked `FAILED`; `--older-than=MINUTES` limits work to older messages and accepts 0–10080.

Run `php artisan fishtrace:cleanup-firebase-telemetry` hourly. Cleanup deletes only entries with `syncStatus=SYNCED` older than retention; `--dry-run` reports without deletion. Failed records stay available for diagnosis/retry. One failure row is retained per device/message; repeated failures increment its retry counter, successful retry resolves it, diagnostic payload persistence uses the telemetry allowlist, and exception text is replaced by a safe class-level message/code before database, audit, notification, or Firebase output. Retention defaults to `FIREBASE_TELEMETRY_RETENTION_HOURS` and can be overridden from administrator system settings within the protected 24–72 hour range.

Run `php artisan fishtrace:reconcile-firebase-assignments --limit=100` to retry assignment mirrors and closures that are `PENDING` or `FAILED`. Active records rebuild device assignments and trip membership from MySQL. Ended records mark device access inactive and remove temporary `/liveTrips/{tripId}` and `/tripMembers/{tripId}` data without deleting permanent telemetry. Errors are sanitized, audited, notified once, and left retryable.
