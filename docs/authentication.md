# Authentication

Flutter authenticates with Laravel Sanctum. A successful login returns one bearer token named for the client device plus a privacy-safe user, role, and primary organization object. Logout revokes the current token; logout-all and password change revoke every token. Login is throttled, disabled/locked accounts are rejected, failed attempts are counted, and last login is recorded. Authenticated API traffic is also limited per user: safe reads receive a higher allowance than mutations, and exhaustion returns HTTP `429` with the stable `TOO_MANY_REQUESTS` API error code.

Password reset requests always return the same message for active, disabled, and unknown accounts. Email addresses are trimmed and case-normalized. Active accounts receive a random six-digit code; only its slow hash is stored. A new request invalidates older codes, codes expire after ten minutes, five failed attempts lock a code, and a successfully verified code cannot be replayed.

Verification returns a 64-character opaque reset token while storing only its SHA-256 hash. The token is bound to the normalized email and original code expiry. Completing the reset transactionally changes the password, deletes every outstanding reset record for the account, revokes all Sanctum sessions, and makes the token single-use. Requests, verification failures, delivery failures, successful verification, invalid reset attempts, and completed resets are audited without storing codes, tokens, or email addresses in clear text. Mail uses the configured Laravel mailer; delivery failure is isolated behind the same enumeration-safe API response and recorded for operations.
