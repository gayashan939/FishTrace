# AI integration

`AI_DRIVER=mock|http` selects deterministic local prediction or a timeout/retry-bounded FastAPI client. Feature aggregation reads permanent MySQL telemetry and calculates current/average/minimum/maximum temperature, duration, humidity, time since catch, and violations. Inputs and results are persisted, and API requests dispatch the batch-unique `RequestSpoilagePrediction` job through the configured queue. With `AI_AUTO_PREDICT=true`, successful telemetry imports dispatch prediction work after the database transaction commits; AI availability never blocks telemetry persistence or Firebase synchronization. AI output is decision support, not an automated safety determination.

The HTTP client sends a bearer token over the configured HTTPS endpoint and rejects unknown risk levels, confidence/probability values outside zero to one, missing probability classes, malformed payloads, and HTTP/connection failures. HIGH predictions generate organization notifications. After the queue exhausts its three attempts, `failed()` persists a sanitized `ai_service_failures` record, audits the terminal state, and sends one operational notification. A later successful retry marks unresolved failures for that batch resolved without deleting their history.

The prediction API uses an explicit response whitelist and never returns stored input features or requester identity. Every response includes `decision_support=true` and a food-safety disclaimer. Successful predictions create a privacy-safe `AI_PREDICTION_ANCHORED` traceability milestone containing only risk, confidence, model version, and the decision-support marker.
