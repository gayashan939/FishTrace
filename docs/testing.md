## Release and integration suites

Run `php artisan fishtrace:release-check` for a safe local diagnostic. Run `composer release-check` in the deployed release after migrations, the frontend build, and `php artisan optimize`; strict mode fails on local/mock drivers, SQLite, debug mode, non-HTTPS URLs, and uncached configuration as well as hard failures. JSON output is available with `php artisan fishtrace:release-check --strict --json`. The command never prints credential paths, tokens, keys, or database credentials.

The normal PHPUnit suite intentionally remains SQLite-only. MySQL acceptance is destructive and is hard-locked to a database named `fishtrace_test`. Create a dedicated database and least-privilege test user, then supply connection values if they differ from the defaults and run:

```powershell
$env:DB_USERNAME='fishtrace_test'
$env:DB_PASSWORD='test-only-password'
composer test:mysql
```

The suite rebuilds only `fishtrace_test`, validates migrations/seeding on MySQL, and starts two independent PHP processes competing for the last retail package. Exactly one sale must commit. Never grant the test user access to a production schema.

Run `npm run test:firebase-rules` to start disposable Auth and Realtime Database emulators and execute the committed rules suite. Firebase CLI 15 requires Java 21 or newer and does not require Firebase login or production credentials. The tests cover default denial, assignment/trip isolation, device impersonation, payload bounds and shape, append-only message IDs, and ordinary-user write denial.

Before production approval, run both opt-in suites and attach their output to the release record. Broader concurrent intake, splitting, device assignment, reservation, recall, external HTTP failure modes, and browser/screen-reader checks remain environment acceptance work.
