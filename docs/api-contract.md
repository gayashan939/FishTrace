# REST API contract

Base path: `/api/v1`. Authenticate using `Authorization: Bearer {sanctum token}`. Login is `POST /auth/login` with `email`, `password`, and `device_name`. Password recovery uses the throttled `/auth/forgot-password`, `/auth/verify-otp`, and `/auth/reset-password` sequence; clients must never infer account existence from the generic request response. Obtain live-data access with `POST /firebase/session` after login.

Success responses contain `data` and `meta.request_id`; errors contain `error.code`, `error.message`, optional `field_errors`, and request metadata. Collections are bounded to 100 items per page. Workflow mutations use dedicated transition routes and return 409 for an invalid current state. Authenticated requests are limited per user to 600 safe reads or 120 mutations per minute; clients receiving HTTP `429` / `TOO_MANY_REQUESTS` must honor `Retry-After` and retry with backoff rather than immediately replaying mutations.

Implemented route groups are auth, Firebase session, administrator users/organizations/read-only roles, private files, database notifications, organization reports/exports, regulator/inspector audit search, boats, fishing trips, catches, batches/QR/timeline, processor intake/ordered processing/inspection/splitting/package labels, retail receiving/inventory/reservations/sales, transport trips/device assignments/live access/history, IoT provisioning, AI predictions, alerts, and public trace. Administrator mutations use dedicated activate/deactivate/unlock/revoke-sessions/reset-password routes and return `409 CONFLICT` when an access-management invariant would be violated. `php artisan route:list --path=api/v1` is the generated source of truth for the current build.
